SPECIFICATION CURVE

Hootsworth: You ran a causal impact analysis and got p=0.03. Great! But did you try other reasonable setups? Would they agree — or flip the conclusion? That's what Specification Curve Analysis (SCA) answers.

WHAT YOU'LL LEARN

  • Why a single model specification can mislead — the "forking paths" problem
  • What SCA is and how it stress-tests analytical choices exhaustively
  • How to read a spec curve chart and indicator matrix
  • Why permutation validation is required on top of SCA
  • How to report honestly: range of estimates, not cherry-picked best

Companion to the Causal Impact deck. Assumes you know BSTS / counterfactual ITS basics.

THE PROBLEM

Every causal impact analysis requires dozens of decisions before you see the result:

  • Which covariates to include?
  • How long a pre-period? Start from October or January?
  • Mask out Christmas? All of November–January?
  • Weekly seasonality (nseasons=7) or biweekly (nseasons=14)?
  • Log-transform the target?
  • Day-of-week as sin/cos, binary weekend, or 7 dummies?

Each of these is a forking path — a point where a reasonable analyst could go either way.

The specification search trap: If you try 48 combinations and report the one with the lowest p-value, you've run a multiple-testing experiment disguised as a single analysis. The "best" spec might just be the one that got lucky with noise.
With just 6 binary choices → 2⁶ = 64 possible specifications
With realistic options (3–5 levels per choice) → hundreds or thousands
► Specification Curve Analysis (SCA) makes this problem the feature: run all reasonable specs, plot them all, and let the distribution speak.

WHAT IS SCA?

Hootsworth: SCA was introduced by Simonsohn, Simmons & Nelson (2020). The idea: instead of defending one specification, run all defensible ones and show the full distribution of results.

THE THREE-STEP RECIPE

① ENUMERATE — List every reasonable analytical choice (covariates, pre-period, masking, seasonality, encoding). Cross them to get the full grid of specifications.
② RUN ALL — Fit the causal impact model under every specification. Record the effect estimate, CI, and p-value for each.
③ PLOT & INTERPRET — Sort specs by effect size. Plot the spec curve (effect bars) with an indicator matrix below showing which choices produced each bar. The shape tells the story.
► SCA does not "pick the best model." It asks: is the conclusion robust to the analytical choices, or does it depend on one lucky configuration?

THE FORKING PATHS

In a causal impact analysis, these are the typical dimensions you vary across specs:

DimensionTypical optionsWhy it matters
Pre-period mode Full range · mask Christmas · mask Nov–Jan · post-holiday trimmed High-variance periods inflate CIs; masking removes them but also removes training data
Seasonality nseasons=7 (weekly) · nseasons=14 (biweekly, captures payday cycles) Biweekly often halves p-value in retail — but only if fortnightly patterns exist
Day-of-week encoding None · sin/cos pair · binary is_weekend · 7 day dummies Redundant with nseasons=7 but needed with nseasons=14
Calendar signals None · Christmas intensity · bank holidays · full (xmas + holidays + payday) Continuous intensity beats binary flags for high-variance events
External signals None · Google Trends (category, daily) · weather · both Category search (near-zero revenue correlation) is paradoxically the strongest covariate
Sale detection None · binary flag · continuous intensity · both (zeroed during treatment) Must be zeroed during the treatment window to prevent contamination
► Masking and seasonal enrichments are mutually exclusive. Masking removes exactly the dates where holiday Gaussian signals are non-zero — making them constant (all zeros) in the pre-period. Pick one: mask to remove holiday variance, OR decompose to model it.

BUILDING THE GRID

A full factorial of all dimensions creates thousands of specs — most are junk. Smart SCA uses curated bundles instead:

BUNDLE STRATEGY

  • Forward stepwise bundles — start from a minimal spec, add one enrichment at a time. Traces "what does each addition buy?" Often the first 2–3 enrichments capture 80% of the improvement.
  • Leave-one-group-out bundles — start from the full spec, drop one enrichment group at a time. Identifies "which group matters most?"
  • Head-to-head bundles — within each dimension, test genuinely different signals against each other (e.g. sin/cos vs binary weekend vs day dummies).

PRACTICAL EXAMPLE — RETAIL SCA

4 pre-period modes × 2 seasonality × 4 DoW × 4 calendar × 3 external × 3 sale
= 1,152 full factorial — but only ~50–100 curated bundles needed
► No hard covariate cap. BSTS uses a horseshoe prior that handles many covariates via shrinkage. If a 9-covariate spec passes the permutation test, the feature count is fine. Use permutation p < 0.10 as the gatekeeper, not an arbitrary covariate budget.

READING THE CHART

Hootsworth: A spec curve has two panels. The top panel is the headline — but the bottom panel (the indicator matrix) is where the insight lives.

TOP PANEL — THE SPEC CURVE

Bars sorted by effect size (left = smallest, right = largest). Each bar = one specification's cumulative effect estimate. CI whiskers show uncertainty. Color marks significance:

  • p < 0.05 — formally significant
  • p 0.05–0.10 — borderline
  • p > 0.10 — not significant

BOTTOM PANEL — INDICATOR MATRIX

A binary grid below the bars. Each row is one analytical choice (e.g. "mask Nov–Jan: yes/no", "include weather: yes/no"). Filled dots show which choices produced each bar. Patterns emerge:

  • If all green bars share "mask_xmas = yes" → masking drives significance
  • If green bars scatter across all rows → result is robust to choices

WHAT TO REPORT

Median effect · IQR · % specs significant · % positive direction
Per-dimension average p improvement when included vs excluded

PERMUTATION ON TOP

SCA ALONE IS NOT ENOUGH

A spec that achieves p=0.03 across the curve looks good — but does the same spec produce p=0.03 at random dates too? If yes, the model is overconfident, not the effect is real.

THE PROTOCOL

  1. Take the top 50 specs from the SCA (sorted by p-value)
  2. For each spec, run 10+ permutation shuffles (random fake treatment dates)
  3. Compute permutation p for each spec: how often does a random date match or beat the real effect?
  4. Any spec with permutation p > 0.10 → flag as potentially spurious
Real finding: In one retail engagement, sale signals alone passed BSTS p-value but failed the permutation test. When combined with external signals (Google Trends category), the combination passed. The external signal carried the robust causal information — the sale flag was just picking up calendar regularity.

MASKING + TIGHT MODELS — THE OVERCONFIDENCE TRAP

Masking high-variance months (e.g. Nov–Jan) leaves only calm data. The model becomes very "sure" of predictions from this calm period, producing low p-values for both real and random intervention dates.

► One retail spec had BSTS p=0.017 but permutation p=0.22 — 11 out of 49 random dates produced effects as large as the real promo. The permutation p is the honest one. Always report both.

THE HONEST REPORT

After running the SCA and permutation validation, here's what to actually say:

What you foundHow to frame it
Pre-registered one spec, it's significant CONFIRMATORY — lead with it. This is the gold standard.
Tested N specs, all significant ROBUST — lead with the median and range. Very strong.
Tested N specs, best one is significant EXPLORATORY — lead with the full range. Best spec is exploratory, not confirmatory. Consider Bonferroni correction: multiply best p by N.
Tested N specs, none significant INCONCLUSIVE — lead with Bayesian posterior probability and direction consistency. "Inconclusive" is a valid result.
The probability inflation trap: If you tested 48 specs and the best gave p=0.039, quoting "96% probability" (1 − 0.039) smuggles the cherry-picked result into a Bayesian-sounding claim. Derive the probability range from a systematic sensitivity rerun. Honest range: ~75–90%, not 80–96%.
► The client doesn't need p < 0.05. They need to know whether to run the promo again. All specs positive + consistent direction is often more useful than one significant p-value.
SUB-CHAPTER · WORKED EXAMPLE

REAL CASE: 448-SPEC SCA

ANONYMIZED · UK E-COMMERCE RETAILER

SETUP

A UK retailer ran a 4-day delivery promo. The analyst ran a Specification Curve Analysis across 448 model variants, varying pre-period mode, seasonality, covariates, and enrichments.

RESULTS SUMMARY

MetricValue
Total specs448
% showing positive effect99.5%
Effect range+£154K to +£408K
Median effect~£280K
Best permutation p0.005 (short clean pre-period)

KEY FINDINGS FROM THE INDICATOR MATRIX

  • Short pre-period dominates low-p specs — Jan–Feb only (51 days). This reflects regime homogeneity: stable post-Christmas data reduces observation error variance, narrowing CIs. Not cherry-picking.
  • Category Google Trends was the single strongest covariate improvement: ~6.5× p-value improvement over baseline, validated by permutation.
  • Sale signals alone failed permutation (perm-p ~0.14) but combined with Trends they passed (perm-p ~0.08). Complementary, not standalone.
  • Weather was the biggest permutation improver (perm-p from 0.098 → 0.059) despite minimal CI impact. Truly exogenous signals help the model explain residual variance at random dates.

QUIZ

Scenario: You ran 60 SCA specs. The best one gives BSTS p = 0.02. The median across all specs gives p = 0.18. Permutation test on the best spec gives perm-p = 0.15.

Your stakeholder asks: "Is the campaign effect statistically significant?"

Reveal answer

No — the result is exploratory, not confirmatory.

  • The best spec (p=0.02) is cherry-picked from 60 options. With Bonferroni correction: 0.02 × 60 = 1.2 — nowhere near significant.
  • The median p=0.18 represents the "typical" specification — not significant.
  • Permutation p=0.15 on the best spec means 15% of random dates look equally good — the model can't reliably distinguish the real intervention from noise.
  • Honest framing: "Our best estimate is a positive effect (99% of specs agree on direction). However, we cannot claim statistical significance — the median p-value is 0.18 and the best spec's significance does not survive permutation validation."

Bonus question: What would you change to improve the analysis?

Reveal answer
  • Shorten the pre-period to a single homogeneous regime (e.g. post-Christmas)
  • Add truly exogenous covariates: weather, category-level Google Trends (not brand-level)
  • Remove covariates that were redundant with nseasons (e.g. cos_dow when nseasons=7)
  • Run a longer campaign next time — 4 days is at the detection limit for BSTS

QUEST COMPLETE

Hootsworth: Specification Curve Analysis turns a weakness (many possible models) into a strength (robustness evidence). The spec curve doesn't find the answer — it shows you whether an answer exists across all reasonable choices.
  • Every analysis has forking paths — covariate choice, pre-period, masking, seasonality. Reporting one spec without acknowledging the others is incomplete at best, misleading at worst.
  • SCA runs all defensible specifications and plots the full distribution. The shape of the curve — not any single bar — is the finding.
  • Read the indicator matrix: if significance clusters around one configuration, the result is fragile. If it's spread across many configurations, it's robust.
  • SCA alone is not enough. Permutation tests validate whether low p-values reflect real effects or model overconfidence. Report both BSTS p and permutation p.
  • Honest framing: median effect, IQR, percentage of specs showing positive direction, percentage significant. Never lead with the cherry-picked best spec unless it was pre-registered.
